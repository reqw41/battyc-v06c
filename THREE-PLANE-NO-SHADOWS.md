# Три плоскости без теней: JS-модели и нативная оптимизация

Ветка `experimental/three-plane-no-shadows-js`, база `a610662`.
Ванильный Вектор-06Ц: i8080 / 3 МГц / 64 КБ, без квазидиска.
A000/C000/E000 — общий восьмицветный framebuffer; 8000..9FFF — невидимая RAM.

ROM после оптимизации: `b299b1746eb246d4c5c364ba7c2b7ebb81ae98e0109080669d3541f8a601908b`.
Неоптимизированный ROM без теней: `9ce94a50f613d0ba7a75e1c97fe90737d11091dce9b5da2ea6ffa2e53f8aa358`.
Он сохранён вместе с символами в `verify/fixtures/three-plane-no-shadows-before`.

## Что изменено

- Перенесены компактные спрайты без падающих теней из последнего варианта 2+2. Светлые детали, чёрная обводка толщиной один пиксель и внутренние тёмные детали сохранены. Бонусы, НЛО и кадры взрывов сохранены. Коллизионные размеры объектов прежние. Фазы шаров и биты подготовлены офлайн в исходных фиксированных резервах; старый генератор сдвигов при первом запуске заменяется тремя NOP только в варианте без теней. Исправлено исходное налезание короткого четвёртого кадра птицы на пятый.
- Перенесены нативные изменения логики из `798b5ad`: декодирование управления, выбор строки/столбца кирпича, сложение координат, финализатор шара. Перед переносом проверены совместимость patch и исходная база; после — JS-оракулы и дифференциальное исполнение старого/нового i8080.
- Изменён внутренний кэш спрайтов: вместо пары E/F хранится `~coverage, lit`. Размер остался два байта на ячейку. Пересчёт маски и пикселей убран из горячей строки блита. В верхней части врага белый пишется в A/C/E; в нижней — цвет в E и чёрная маска в A/C.
- Белый блит развёрнут по четыре строки с входом в нужное место для остатка; источник читается через SP/POP. SP восстанавливается перед EI. Адреса 32 кэшей теперь выбираются таблицей вместо ветвления и умножений. Дополнительная RAM не выделялась.

## Замеры в тактах

vector06js, исполнение настоящих инструкций i8080 и растра. 65 управляемых шагов на сцену, среднее последних 45 после прогрева. Позиции задаются перед логикой; реальные обработчики и вывод выполняются без подмены. Столбцы CPU исключают WaitVideoFrame. Полный шаг включает ожидание; 16 тактов аппаратного входа IRQ за прерывание учтены отдельно в budget JSON. Это игровые шаги, а не частота видимого растра. Попадания в кирпичи и потеря жизни в эти сцены не входят.

| Сцена (везде есть бита) | CPU до | CPU после | Полный шаг после | Шагов/с после |
|---|---:|---:|---:|---:|
| Один шар | 50 839 | 45 826 | 59 869 | ≈50 |
| Шар + бонус | 77 821 | 70 002 | 89 732 | 33,4 |
| Шар + НЛО | 89 073 | 77 555 | 111 786 | 26,8 |
| Шар + птица | 85 353 | 74 853 | 103 316 | 29,0 |
| Три шара | 83 449 | 76 679 | 97 112 | 30,9 |
| Три шара + бонус + НЛО | 149 928 | 133 686 | 138 610 | 21,6 |

Тяжёлая сцена: CPU быстрее на **10,83%**, 49,976 → 44,562 мс; полный шаг 51,155 → 46,203 мс (с отдельно учтённым аппаратным входом IRQ — 46,210 мс). Бюджет двух растровых кадров — 119 808 тактов (39,936 мс). После оптимизации CPU этой сцены всё ещё превышает его на 13 878 тактов. Холодный максимальный шаг стенда — 82,583 мс; прогрев не доказывает стабильные 25 Гц во всей игре.

Разбиение тяжёлого шага на непересекающиеся блоки:

| Блок | До | После |
|---|---:|---:|
| Логика/управление | 26 521 | 22 270 |
| Подготовка | 60 | 60 |
| Восстановление старых объектов | 23 267 | 23 267 |
| Сохранение фона + вывод объектов | 98 782 | 86 879 |

| Бегущие точки биты | 1 029 | 985 |

Средние округлены независимо; строки могут расходиться с суммой на один такт. Вложенные процедуры внутри вывода (не складывать с таблицей выше): PreparedDraw 51 914 → 40 602; SUSaveObject 29 347 → 29 302; SpriteCachePrepare 5 547 → 4 853. Сохранение фона вместе с восстановлением — около 52 570 тактов, 39,3% CPU кадра. Это главный остающийся расход общего framebuffer. Следующая архитектурная оптимизация должна сокращать сам объём save/restore, с проверкой перекрытий и изменений фона; дальнейшее ускорение только блита не уберёт этот расход.

Выстрел врага, отдельный согласованный стенд с 65 шагами: три шара + НЛО + вертикальная бомба, CPU 136 044 → 123 830 тактов, полный шаг 142 312 → 128 038 (42,679 мс). Все восемь X-фаз: CPU 135 365 → 123 155, полный шаг 127 241 (42,414 мс). Прогретых пересборок кэша нет.

Последний 2+2 без теней (`8fe04e11…`) проверен на тех же шести сценах. В тяжёлой сцене у него CPU 106 163, полный шаг 114 466 (38,155 мс, 26,2 шага/с). Три общие плоскости сейчас требуют на 25,9% больше CPU. Этот эксперимент основной вариант 2+2 не заменяет.

## Проверки

- JS-модель формата/трёх плоскостей: 100 663 296 байтовых сравнений; 65 536 нативных проверок кэша с произвольными масками; 4 160 сочетаний высоты, отсечения и цветового перехода. Extra RAM: 0.
- Нативная логика: 103 936 случаев JS/8080; ещё 3 200 дифференциальных запусков пяти настоящих обработчиков. Сравнивается логическое состояние и видимые A/C/E; 8000..9FFF содержит изменённый внутренний кэш и не является картинкой.
- Спрайты: 1 477 последовательных сцен, 4 431 побайтное сравнение плоскостей; сдвиги, обрезка, перекрытия 11 объектов, исчезновение, статическое окно раунда, изменения фона.
- Маски без теней: 34 ассета, 6 712 светлых деталей, 1 639 проверок обводки, 2 184 координаты сдвинутых фаз; 26 неизменённых эффектов/бонусов; размеры коллизий прежние.
- Кирпичи: 370 отдельных и 370 последовательных разрушений на четырёх уровнях; бонусы/формы биты: 28 случаев; возврат после смерти/смены игрока: четыре режима; осколки: пять естественных разлётов по 50 шагов.
- ВИ53: три голоса, восемь нот, 1,086 с; старт SFX через 1,059 мс после события. Warm reset/векторы проверены.
- 12 000 растровых кадров естественной партии, без неожиданных сбросов; бомбы и пойманные бонусы наблюдались. Smash естественно не выпал, проверен управляемым тестом. Максимальный наблюдавшийся обычный стек 44 Б из 96. Ассемблер: `--i8080 --nofakes`, 0 ошибок/предупреждений.

**Мерцание сохраняется.** В тесте неподвижных врагов на 1 536 растровых кадрах: до оптимизации 647 полностью пустых, 1 087 неполных; после — 631 полностью пустых, 1 115 неполных (пустые входят в неполные). Ускорение CPU не устранило промежуток глобального стирания между restore и draw. Итоговые пиксели корректны, но изображение по лучу пока не гарантировано. На MiSTer и в Emu80 эту новую сборку не проверяли.

## Воспроизведение

```sh
./build-no-shadows.sh
node verify/test-three-plane-native-models.js
BATTY_LOGIC_BEFORE=verify/fixtures/three-plane-no-shadows-before node verify/test-native-logic.js
BATTY_LOGIC_BEFORE=verify/fixtures/three-plane-no-shadows-before node verify/test-native-logic-gameplay.js
node verify/test-three-plane-render.js
BATTY_BENCH_OUT=outputs/batty-three-no-shadows-optimized-speed.json node verify/measure-object-speed.js
BATTY_BUDGET_COMPOSITE_REFERENCE=outputs/batty-three-no-shadows-optimized-speed.json BATTY_BUDGET_OUT=outputs/batty-three-no-shadows-optimized-budget.json node verify/profile-three-plane-budget.js
BATTY_BENCH_OUT=outputs/batty-three-no-shadows-shot-optimized.json node verify/measure-enemy-shot.js
```

Обычный `./build-three-plane.sh` собирает с исходными тенями и новым форматом кэша. Для воспроизведения старого неоптимизированного варианта используйте сохранённые ROM/символы; не сравнивайте их кэш побайтно с новым форматом. Отчёты с SHA находятся в `outputs/batty-three-no-shadows-*`.
