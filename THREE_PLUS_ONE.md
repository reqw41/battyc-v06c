# Batty: 3+1, белые спрайты и восемь цветов фона

Экспериментальная ветка `experimental/three-plus-one-mono-js`, обычный Вектор-06Ц, i8080 3 МГц, 64 КБ. Четыре видеоплоскости видимы. 8000–9FFF — белые спрайты; A/C/E — фон. Дополнительной RAM нет. ROM загружается с 0100 и заканчивается на 7FFF (32512 байт).

## Цвета и вывод

Индексы 0–7 выбирают восемь цветов фона. Все индексы 8–15 дают белый: установка бита в плоскости 8000 перекрывает любой цвет фона. Мяч, бонусы, враги, пули, осколки и ракета выводятся белыми, без чёрной обводки и теней.

На первом уровне бумага синяя. Отдельная нижняя полоса (логический Y=168–191) имеет фон с индексом 1: A/C=0, E=1. Под обычной битой E сбрасывается по маске её контура. Белые детали лежат в 8000, а бегающие точки открывают чёрную подложку. После движения старые участки полосы восстанавливаются единицами в E. Это исключение из одноплоскостного вывода; сохранённый фон не нужен. При полёте ракеты биты выше полосы выводятся без обводки.

Фон первого уровня: `00,C0,80,40,07,38,3F,F8`; спрайтовая половина палитры: восемь `FF`. Цвет бумаги и узора меняется по четырём темам уровней.

JS-модель проверяет вывод через полный независимый OR всех объектов. В i8080 перенесён быстрый путь для объектов, у которых объединение старого и нового прямоугольника не пересекает такое же объединение другого объекта. Их новый прямоугольник копируется непосредственно, а очищаются только уходящие края. Неизменившиеся границы не очищаются. Пересекающиеся объекты используют общий OR-композитор; save-under для движущихся объектов отсутствует.

62 спрайта, включая значки жизней и заголовки счёта, переведены JS-генератором в столбцы (~маска, белые пиксели) с сохранением выделений и адресов. Изолированные белые спрайты сдвигаются непосредственно при выводе через SP, без промежуточного кэша. Кэш оставлен для пересечений, биты с чёрной окантовкой и статического HUD. Два списка описателей по 77 байт меняются местами без копирования. Фон под битой восстанавливается в E; остальные движущиеся объекты записывают только 8000.

## Память

Код и исходная графика находятся ниже 6B00; стек 6BA0–6BFF (96 байт). Карта уровня — 6D00; атрибуты — 6E00–70FF. Полосы композиции — 7100–713F, рабочие переменные — 71D1. Процедура вывода и её описатели — 7200–79FD; границы изоляции — 6B00–6B5C. Кеши — 7A00–7FE3; окно раунда временно использует 400 байт первого кеша после удаления объектов. Код в видеопамяти отсутствует.

## Измерения

`verify/measure-object-speed.js`: 65 управляемых шагов, 45 прогретых. Координаты задаются перед логикой. Период измеряется между началами вывода и включает вход IRQ. Выбрана максимальная скорость с переменным периодом, без принудительной привязки к двум растрам.

Текущие замеры и бюджет приведены в [THREE_PLUS_ONE_PACING.md](THREE_PLUS_ONE_PACING.md); история оптимизации самого вывода — в [THREE_PLUS_ONE_FAST.md](THREE_PLUS_ONE_FAST.md). В контрольной тяжёлой сцене средний период 33,49 мс, пик 39,54 мс; с бомбой врага пик 39,936 мс. Полноценный игровой прогон выявляет более долгие события: гарантия 25 Гц для всей игры пока не достигнута.

Проверки: 2500 кадров независимой JS-модели, 1826 нативных сцен / 7304 сравнения плоскостей; границы кешей, A/C без записей в движущемся выводе, восстановление E под битой, холодное окно раунда; 740 восстановлений кирпичей на четырёх уровнях, 250 кадров разлёта, четыре продолжения после смерти, 28 бонусов, музыка ВИ53 и SFX, тёплый перезапуск. Естественное покрытие редких бонусов зависит от момента старта; неполное покрытие и ограничения прогонов указаны в отчёте. Для ракеты и конца раунда удалены оставшиеся старые циклы вывода.

Растровые проверки фиксированных позиций включают врагов, бонусы и реальные пересечения. Нулевые исчезновения в этих наборах не доказывают отсутствие разрыва при движении.

## Сборка и проверки

```sh
sh build-three-plus-one.sh
node verify/model-three-plus-one.js
node verify/test-three-plus-one.js
node verify/test-mono-sparks.js
BATTY_TEST_OUT=outputs/batty-three-plus-one-resume.json node verify/test-mono-resume.js
BATTY_TEST_OUT=outputs/batty-three-plus-one-bricks.json node verify/test-three-plane-bricks.js
BATTY_TEST_OUT=outputs/batty-three-plus-one-bonus.json node verify/test-mono-bonus.js
BATTY_TEST_OUT=outputs/batty-three-plus-one-audio.json node verify/test-audio-start.js
node verify/test-mono-warm.js
BATTY_BENCH_OUT=outputs/batty-three-plus-one-speed.json node verify/measure-object-speed.js
BATTY_RASTER_OUT=outputs/batty-three-plus-one-enemy-raster.json node verify/test-mono-raster.js
BATTY_RASTER_OVERLAP=1 BATTY_RASTER_OUT=outputs/batty-three-plus-one-overlap-raster.json node verify/test-mono-raster.js
BATTY_RASTER_BONUS=1 BATTY_RASTER_OUT=outputs/batty-three-plus-one-bonus-raster.json node verify/test-mono-raster.js
BATTY_GAMEPLAY_FRAMES=9000 BATTY_GAMEPLAY_OUT=outputs/batty-three-plus-one-natural.json node verify/test-natural-bonus-gameplay.js
```

Нужны sjasmplus с i8080/--nofakes, Node.js и локальная копия vector06js (VECTOR06JS_ROOT). В этой ветке следует использовать build-three-plus-one.sh; прежние скрипты относятся к ранее сохранённым экспериментам.
