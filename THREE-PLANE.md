# Batty: три общие плоскости и save-under

Новый эксперимент без теней и с нативной оптимизацией описан в [THREE-PLANE-NO-SHADOWS.md](THREE-PLANE-NO-SHADOWS.md). Ниже — исторический отчёт исходной версии с тенями.

Локальная ветка `experimental/three-plane-save-under`, отдельный checkout. База: локальная четырёхплоскостная сборка, снимок `c77b911` (ROM `8b95fcdf5465959f965862b4f13d310ac3feb6d78db67f757fc6e86c4b5b8e28`).

**Эксперимент работоспособен, но медленнее базы и заметно сильнее мерцает. Основную сборку пока им не заменять.** Это первый вариант общего framebuffer, а не полный перенос оптимизированного рендерера kvalley.

Текущий ROM SHA256: `94c108c4c08c25d16e8e74e974b295e4dbd570d528d695c6cbaad0cbd99d03a4`.

## Архитектура

Обычный i8080 / 3 МГц / 64 КБ. Port 10 всегда 0, квазидиска нет.

A000/C000/E000 — общая восьмицветная картинка. Индекс 0 — чёрный, 1 — цвет врага по уровню, 7 — белый; фон использует чётные индексы. Обводки и тени очищают все три плоскости под маской. Палитра дублируется в индексах 8..15: содержимое 8000..9FFF невидимо.

Все движущиеся объекты, включая осколки, сохраняют прямоугольник до вывода. Перед следующим выводом прямоугольники восстанавливаются в обратном порядке; это сохраняет корректность перекрытий. Чтение фона или его изменение предварительно восстанавливает старые объекты, поэтому разрушенный кирпич не возвращается из save-under. Окно начала раунда имеет отдельный сохранённый фон, HUD постоянный.

Save/restore читают источник через SP/POP, столбцы развёрнуты до 64 строк. Готовые спрайты также читаются через SP/POP, три плоскости пишутся подряд для каждой строки. SP восстанавливается до EI; CALL/PUSH внутри перехвата нет. E/F остаётся только внутренним форматом данных спрайта, отдельного слоя спрайтов в видеопамяти больше нет.

У биты и шаров есть отдельные кэши. Ключ учитывает X-фазу уже сдвинутых исходных спрайтов оригинала, поэтому нормальные шарики не перезаписывают один кэш каждый шаг.

## Память

| Адреса | Назначение |
|---|---|
| 8000–8DFF | 3584 Б данных save-under, компактные записи находятся ниже 6B00 |
| 8E00–8FBF | 448 Б промежуточного спрайта |
| 8FC0–8FFF | 64 Б ключей кэшей |
| 9000–96FF | 8 фаз биты по 224 Б |
| 9700–9AFF | 8 фаз шарика по 128 Б |
| 9B00–9FFF | 1280 Б под окно раунда, используется 1200 Б |
| A000–FFFF | три видимые плоскости, 24 КБ |

Кэши бонусов и врагов продолжают использовать прежние свободные участки ниже 8000; добавлены фазы 0 по 7840 и 78C0. Основной код заканчивается на 69A3, расширение — на 776A, хвост — на 7FC1. Стек 6BA0–6BFF, наблюдавшийся максимум 44 Б из 96.

## Замеры

vector06js с настоящими i8080/raster/ВИ53, одинаковый стенд из 65 управляемых шагов. Среднее последних 45, такты instruction(); аппаратный вход IRQ вынесен отдельно в budget.json. Позиции задаются перед логикой, попадания в кирпичи и смерть в этот замер не включены.

Тяжёлая сцена — бита, три шара, бонус, НЛО: CPU 143282 → 181780 тактов (+26.9%), полный шаг 150019 → 187160 (+24.8%), 20.00 → 16.03 шагов/с. В прогретой тяжёлой сцене построений кэша нет. Плавная траектория без скачка 7→0: CPU 181850, полный шаг 183206 тактов.

Внутри тяжёлого шага (включающие времена, не складывать вложенные строки):

Замена композитора оказалась дороже: теперь каждый прямоугольник читается для сохранения, возвращается на экран и маскируется в трёх плоскостях. В отличие от kvalley здесь нет выборочного одно-/двухплоскостного вывода и его оптимизаций пачки по лучу.

## Проверки и ограничения

* 1477 последовательных сцен / 4431 побайтное сравнение всех трёх плоскостей: все ассеты, сдвиги 0..7, обрезка, 11 пересекающихся объектов, смена кадров и исчезновение; фон, атрибуты и окно раунда восстановлены.
* 370 одиночных + 370 последовательных разрушений кирпичей, четыре уровня и магниты: фон совпадает со свежим выводом A/C/E.
* 28 сочетаний бонусов и форм биты; пять естественных разлётов по 50 шагов; четыре режима потери жизни/смены игрока. У того же игрока нет полной перерисовки уровня.
* Трёхканальная заставка ВИ53: 8 нот, 1.083 с; начало стартового SFX через 1.295 мс после события. Warm reset и векторы проверены.
* 12000 реальных растровых кадров партии: 10 естественных бонусов, 8 поймано, 11 бомб, враги; неожиданных сбросов нет. Smash в этой партии не выпал, он покрыт управляемыми тестами.

**Растр регрессирует.** При неподвижных координатах врагов: 597 пустых и 904 неполных кадра из 1536; бонуса: 72 пустых и 152 неполных из 768. В текущей четырёхплоскостной сборке аналогичные проверки не находили пустых/неполных кадров. Здесь глобальное восстановление убирает старую картинку задолго до нового блита; при 40–60 мс вывода это видно лучу. Корректные конечные пиксели не означают отсутствие мерцания. Пока не добавлены подготовка до изменения экрана и безопасная локальная/групповая замена изображения, вариант остаётся экспериментальным.

На MiSTer и Emu80 эту ветку не проверяли.

## Сборка и воспроизведение

`./build-three-plane.sh` использует `../sjasmplus/sjasmplus`, либо задайте переменную SJASMPLUS. Нужны Node.js и vector06js; путь можно задать VECTOR06JS_ROOT.

Из корня этой ветки:

```sh
node verify/test-three-plane-render.js
node verify/test-three-plane-bricks.js
node verify/test-three-plane-resume.js
node verify/test-three-plane-sparks.js
node verify/measure-object-speed.js
node verify/profile-three-plane-budget.js
node verify/test-three-plane-raster.js
BATTY_RASTER_BONUS=1 node verify/test-three-plane-raster.js
node verify/test-audio-start.js .
node verify/test-prepared-warm-start.js
BATTY_GAMEPLAY_FRAMES=12000 BATTY_GAMEPLAY_REQUIRE_SMASH=0 node verify/test-natural-bonus-gameplay.js .
node verify/test-bonus-effects.js .
```

Для замера скорости задайте BATTY_BENCH_OUT=outputs/batty-three-plane-speed.json, если затем запускаете бюджет; бюджет проверяет SHA и точное совпадение времени с этим JSON.

Локальный diff эксперимента: `git diff c77b911..HEAD`. Исторические описания четырёхплоскостной базы сохранены отдельно.
