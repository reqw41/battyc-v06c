# Локальные группы и композиция Batty, i8080

Сделаны пункты 1 и 2: JS-модель, перенос на настоящий i8080 и измерение на инструкционном эмуляторе с реальным растром. **Мерцание существенно уменьшилось; скорость ухудшилась. Тяжёлая сцена не укладывается в 25 Гц.** Эксперимент сохранён в ветке `experimental/three-plane-local-compositor-js`; исходная сборка сохранена отдельным fixture и в прежних артефактах.

## Что изменено

Для каждого из 11 владельцев строится область старого и нового положения. Пересекающиеся области объединяются в группы. Это консервативные прямоугольные объединения: они безопасны для восстановления фона, но могут объединять пустые промежутки при больших перемещениях.

Одиночный объект выводится сразу готовыми пикселями из сохранённого фона, без предварительного стирания всей области на экране. При одинаковом габарите фон используется повторно. При движении общая часть копируется из предыдущего сохранения, новые края читаются с экрана; после вывода восстанавливаются только освободившиеся края. Для одинакового вертикального интервала есть сокращённый путь проверки столбцов. Белые строки развёрнуты по четыре; маска/пиксель читаются через SP.

Пересекающаяся группа собирается в RAM по одному столбцу и полосе до 32 строк. Сначала читается текущая картинка, затем в обратном порядке снимаются старые объекты; новые объекты сохраняют фон и накладываются в обычном порядке. Только готовые C/E попадают в VRAM. SP читает пары строк при окончательном выводе. Фон предыдущего поколения не перезаписывается до завершения группы.

Порядок: бонус, три шара, пули, биты, враг, ракета. Для осколков принят тот же порядок; проверка пересечений учитывает его. Форма и счётчик Smash подготавливаются один раз за тик, включая совместимый путь для нестандартных объектов из тестов.

Три видимые плоскости A/C/E сохранены; спрайты изменяют C/E. Чёрная обводка, белый и цвет врага остаются прежними. Тени отсутствуют, как в исходной сборке этого эксперимента.

## Мерцание на реальном растре

По 64 растровых кадра на сцену после прогрева, разные высоты, фазы X, UFO/птица и лёгкая/тяжёлая загрузка. Проверяются видимые белые/цветные пиксели исходной маски, а не только конечная VRAM.

| Набор | Кадров | Полное исчезновение до → после | Частичное до → после |
|---|---:|---:|---:|
| enemy | 1536 | 1069 → 0 | 1340 → 0 |
| bonus | 768 | 40 → 0 | 66 → 0 |
| overlap | 1536 | 942 → 6 | 1313 → 7 |

В наборе overlap объекты действительно пересекаются, поэтому выполняется RAM-композиция группы. Шесть оставшихся исчезновений пришлись на лёгкую сцену UFO, X-фаза 0, Y=40. Замер не атрибутирует их причину. Нулевой результат в обычном наборе не является доказательством полного отсутствия мерцания во всей игре.

При движении — 0 полных исчезновений из 1536; проверяется объединение восьми X и четырёх Y положений. Все такие кадры частичные относительно полного объединения. Это проверка отсутствия полного пропадания, **не доказательство отсутствия разрыва или смешивания разных положений**.

## Память

Дополнительной RAM и квазидиска нет. Невидимая плоскость 8000–9FFF игнорируется палитрой и содержит обычные данные и часть кода. Очистка экрана теперь сохраняет эту RAM; видимые A/C/E очищаются как раньше. ROM 40660 байт, загружается с 0100, последний байт 9FD3.

| Область | Назначение |
|---|---|
| 8000–84FF | background bank 0, 1280 байт |
| 8500–89FF | background bank 1, 1280 байт |
| 8A00–8AFF | uncached mask, 256 байт |
| 8B00–8C3F | metadata, 320 байт |
| 8C40–8FB2 | compositor code 1, 883 байт |
| 8FC0–8FFF | cache tags, 64 байт |
| 9000–957F | bat phases, 1408 байт |
| 9580–977F | ball phases, 512 байт |
| 9780–979F | scratch C, 32 байт |
| 9880–989F | scratch E, 32 байт |
| 98A0–9FD3 | compositor code 2, 1844 байт |

Два поколения сохранённого фона: 2496 байт фактических слотов. Временная картинка C/E: 64 байта. Окно начала раунда временно использует 1200 байт первого банка после удаления движущихся объектов; оно восстанавливается до их следующего вывода. Данные фона чередуют E/C, столбец за столбцом сверху вниз, включая чётное округление высоты. Старый трёхплоскостной формат сохранён для холодного окна и совместимых процедур.

Кеш биты уменьшен до 176 байт на фазу (максимум маски 162), шара — до 64 (максимум 56). Все допустимые кадры проверены в JS, диапазоны RAM не пересекаются. Эта компоновка требует сборки без теней; обычный build-three-plane.sh выбирает её, несовместимый режим отвергается ассемблером.

## Проверки и воспроизведение

JS-модель: 2500 кадров, 7280 групп, включая старые/новые пересечения, исчезновение и телепортации. Независимая полная перерисовка и обратное восстановление совпали. Native: 1977 сцен, 5931 сравнений плоскостей; проверены записи только готовых пикселей в новом движущемся пути, точное восстановление фона и сохранение скрытого кода при reset.

Также прошли 740 случаев восстановления кирпичей, 250 кадров осколков, четыре сценария продолжения после смерти, 28 проверок бонусов, трёхканальная заставка/SFX, тёплый перезапуск, старые процедуры SP/save-under и 12000 естественных растровых кадров игры без сбросов. Стек не пересекает 6BA0; в продолжениях после смерти проверено до 44 байт при резерве 96.
